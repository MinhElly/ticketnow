### 3. `booking-service` chuyển sang gRPC client

- Test `GrpcSeatInventoryClientTests`: map success/conflict, release/confirm,
  và deadline 100 ms thực sự trả `DEADLINE_EXCEEDED` khi server chậm 1 giây.

### 4. Scheduled Worker `HoldExpired`

- [HoldExpiredWorker](file:///C:/Code/ticketnow/seat-inventory/src/main/java/com/minh/seatinventory/scheduler/HoldExpiredWorker.java):
  `@Scheduled(fixedDelay=30s, initialDelay=15s)`, có thể đổi bằng
  `HOLD_EXPIRY_SWEEP_MS` / `HOLD_EXPIRY_INITIAL_DELAY_MS`; tắt bằng
  `HOLD_EXPIRY_ENABLED=false`.
- Query `findExpiredHoldsForUpdate` dùng `PESSIMISTIC_WRITE` trên các ghế
  `HELD` có `held_until < now`, đặt lại `AVAILABLE`, xóa `held_by_booking`/`held_until`.
- Dọn Redis key `seat:{eventId}:{seatId}` bằng Lua `DELETE_IF_MATCH`: chỉ xóa khi
  giá trị vẫn là `HELD:{bookingId}`, tránh xóa nhầm ghế vừa được booking khác giữ lại.
- API `GET /seats` vẫn trả trạng thái `AVAILABLE` ngay khi hold hết hạn, không đợi sweep.

## Ghi chú và giới hạn còn lại

1. **Benchmark chưa có số liệu thực tế**: hạ tầng script đã sẵn sàng, nhưng chưa chạy
   20.000 VU trong phiên bàn giao này. Không đưa số liệu giả vào báo cáo.
2. **gRPC server chưa xác thực JWT**: booking-service có lan truyền metadata
   `authorization`, nhưng server chưa cài interceptor xác thực. Đây là internal
   endpoint trong Compose; trước khi mở ra mạng ngoài cần bổ sung JWT interceptor
   và network policy.
3. **`event-service` vẫn gọi REST** để khởi tạo ghế; hợp đồng gRPC `InitializeSeats`
   đã sẵn sàng để chuyển ở giai đoạn sau.
4. **`seat.lock.strategy` vẫn đọc lúc khởi động**, chưa có `@RefreshScope`; khi
   benchmark đổi chiến lược phải restart `seat-inventory`.
5. **Không commit token/password/kết quả benchmark chứa dữ liệu nhạy cảm**;
   `load-tests/results/` chỉ nên chứa summary JSON local.
